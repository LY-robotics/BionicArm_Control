# SANPO 双 STM32 应用命令、电机状态与参数操作教程

## 1. 当前工程的通信结构

工程使用原厂 USB CDC 的 `ST` 标准帧承载新增板级应用命令。PC 不直接控制 GPIO 或步进脉冲，流程如下：

```text
PC SDK
  ↓ USB CDC / ST帧
STM32应用解析
  ↓ CAN标准帧
电机
  ↓ CAN状态反馈
STM32状态缓存
  ↓ USB CDC / ST响应帧
PC SDK
```

两个 USB 串口分别对应两颗 STM32，但 Windows 分配的 COM 编号可能变化。必须通过 `BOARD_INFO` 返回的 `board_id` 判断实际芯片。

| 返回 board_id | 控制范围 |
|---:|---|
| 1 | STM32(1)，物理 CAN-1、CAN-2 |
| 2 | STM32(2)，物理 CAN-3、CAN-4 |

应用请求使用标准 CAN 帧 ID `0x7F0`，响应使用 `0x7F1`，USB channel 使用 `0xFE`。发送应用帧前必须确认电机总线没有占用 `0x7F0/0x7F1`。

## 2. 支持的应用命令

### 2.1 命令总表

| 命令 | 值 | 请求数据 | 作用 |
|---|---:|---|---|
| `BOARD_INFO` | `0x01` | 无 | 查询芯片身份、CAN映射和协议版本 |
| `MOVE_JOINT` | `0x02` | 关节号、目标角度、速度 | 按关节角度和速度控制电机 |
| `GET_STATE` | `0x03` | 关节号 | 获取指定关节缓存状态 |
| `STOP_ALL` | `0x04` | 无 | 向全部配置电机发送停止/失能命令 |
| `HEARTBEAT` | `0x05` | 无 | 保持PC控制权，防止超时急停 |
| `HOME` | `0x06` | 关节号 | 向电机发送回零命令 |
| `CLEAR_FAULT` | `0x07` | 关节号 | 向电机发送清故障命令 |

响应数据的前两个字节固定为：

```text
命令值 | 0x80，状态码
```

例如 `BOARD_INFO` 成功响应的数据以 `81 00` 开头。

### 2.2 BOARD_INFO

请求帧：

```text
53 54 FE 00 00 07 F0 01 01 0D 0A
```

响应数据：

```text
81 status board_id arm_id can_a can_b joint_count protocol_version
```

成功示例（芯片1）：

```text
53 54 FE 00 00 07 F1 08 81 00 01 01 01 02 05 01 0D 0A
```

成功示例（芯片2）：

```text
53 54 FE 00 00 07 F1 08 81 00 02 02 03 04 05 01 0D 0A
```

### 2.3 MOVE_JOINT

请求数据布局：

```text
02
joint_id                         1字节
angle_raw                        int32，小端，角度×100
speed_raw                        uint16，小端，rpm×100
```

总数据长度为 8 字节。例如关节1移动到 `10.00°`、速度 `1.00rpm`：

```text
02 01 E8 03 00 00 64 00
```

STM32执行前会检查：

- 关节号是否存在；
- 目标角度是否在 `min_deg` 到 `max_deg` 内；
- 速度是否大于0；
- 速度是否不超过 `max_rpm`；
- CAN发送是否成功。

### 2.4 GET_STATE

请求数据：

```text
03 joint_id
```

成功响应数据：

```text
83 00 joint_id angle_raw speed_raw fault
```

其中 `angle_raw` 和 `speed_raw` 为小端 `int16`：

```text
angle_deg = angle_raw / 100.0
speed_rpm = speed_raw / 100.0
```

未连接电机时会返回状态码 `04`，即 `OFFLINE`，这是正常现象。

### 2.5 STOP_ALL

请求数据只有：

```text
04
```

STM32向全部配置电机发送 `0xCF` 停止/失能命令，并将缓存模式设置为 `DISABLED`。

### 2.6 HEARTBEAT

请求数据：

```text
05
```

PC控制期间应周期发送心跳。当前超时时间为：

```c
#define SANPO_PC_TIMEOUT_MS 1000U
```

超过1秒没有收到心跳或其他应用命令时，STM32会向全部配置电机发送停止命令，并释放应用CAN控制权。

### 2.7 HOME 和 CLEAR_FAULT

请求格式分别为：

```text
06 joint_id
07 joint_id
```

当前实现发送的电机CAN命令分别为：

```text
HOME        0xC4
CLEAR_FAULT 0xAF
```

这两个字节必须与实际电机协议一致。若电机厂商协议不同，应修改 `sanpo_motor_manager.c`，不能仅修改PC端。

## 3. 状态监测内容

STM32对每个配置关节维护一个状态结构，当前可以监测：

| 字段 | 含义 |
|---|---|
| `online` | 是否在超时时间内收到电机CAN反馈 |
| `actual_deg` | 根据电机反馈角度、减速比、方向和零点换算后的关节角度 |
| `target_deg` | 最近一次下发的目标角度 |
| `speed_rpm` | 电机反馈速度 |
| `current_a` | 电机反馈电流 |
| `fault` | 电机故障字节 |
| `mode` | 离线、运动、就绪、禁用或故障 |
| `done` | 目标角度误差和速度均满足完成条件 |
| `last_rx_ms` | 最近一次反馈时间戳 |

当前只解析两种反馈：

```text
0xA4：位置、速度、电流状态反馈
0xAE：故障状态反馈
```

`0xA4` 的当前解析约定为：

```text
data[2:4] 电流，单位0.001A
data[4:6] 速度，单位0.01rpm
data[6:8] 单圈角度原始值，范围按16384计数
```

如果实际电机反馈字节定义不同，必须修改 `SanpoMotor_OnCan()`。

## 4. 电机参数修改位置

所有关节基础参数集中在：

```text
Core/App/config/sanpo_joint_config.h
```

当前参考配置：

| 关节 | 电机ID | 本地CAN | 减速比 | 方向 | 零点 | 软限位 | 最大转速 | 最大电流 |
|---:|---:|---:|---:|---:|---:|---|---:|---:|
| 1 | 51 | 1 | 3.0 | +1 | 0° | -110°～110° | 5rpm | 0.5A |
| 2 | 56 | 1 | 3.0 | +1 | 0° | -170°～120° | 5rpm | 0.5A |
| 3 | 16 | 1 | 4.0 | +1 | 0° | -180°～180° | 5rpm | 0.5A |
| 4 | 11 | 1 | 4.2 | +1 | 0° | -90°～150° | 5rpm | 0.5A |
| 5 | 22 | 1 | 1.0 | +1 | 0° | -120°～120° | 5rpm | 0.5A |

这些值是当前包中参考值，不能直接视为最终量产参数。

### 4.1 修改电机ID

例如把关节1电机ID改为 `52`：

```c
{1U, 52U, 1U, 1, 3.0f, 0.0f, -110.0f, 110.0f, 5.0f, 0.5f},
```

电机ID必须与实际电机拨码或配置一致，且不能与同一CAN总线其他节点重复。

### 4.2 修改CAN通道

芯片1的本地通道只能使用 `1` 或 `2`：

```c
{1U, 51U, 2U, 1, 3.0f, ...},
```

芯片2编译时仍使用本地通道 `1` 或 `2`，但其物理映射分别是 CAN-3/CAN-4。不要在配置表中填写 `3` 或 `4`，当前固件的 `GetCan()` 只接受本地通道1/2。

### 4.3 修改方向

方向只能填写 `1` 或 `-1`：

```c
direction = 1     // 角度正方向与电机反馈一致
direction = -1    // 角度正方向与电机反馈相反
```

第一次测试必须用极小角度确认方向，方向错误时立即停止，不要直接扩大运动范围。

### 4.4 修改减速比

公式为：

```text
电机目标角度 = (关节目标角度 - zero_deg)
              × direction
              × gear_ratio
```

反馈角度则按反方向换算回关节角度。减速比必须使用实际机械传动比，而不是电机编码器分辨率。

### 4.5 修改零点

`zero_deg` 是“电机反馈机械位置对应的关节角度”。例如机械装配基准位置定义为 `15°`：

```c
{1U, 51U, 1U, 1, 3.0f, 15.0f, -110.0f, 110.0f, 5.0f, 0.5f},
```

零点修改后必须重新验证正负方向和软限位。

### 4.6 修改软限位

```c
min_deg
max_deg
```

`MOVE_JOINT` 在发送CAN前执行限位判断，越界命令不会下发到电机。软限位不是硬件急停，不能替代机械限位、急停开关或驱动器保护。

### 4.7 修改最大速度和最大电流

```c
max_rpm
max_current_a
```

`max_rpm` 用于PC命令输入校验。`max_current_a` 会转换成毫安整数发送到电机：

```text
0.5A → 500
```

当前电机控制帧使用：

```text
0xB2：速度
0xB3：最大电流
0xC2：位置
```

如果电机协议中电流单位或命令格式不同，必须同步修改 `SanpoMotor_MoveJoint()`。

## 5. 双芯片编译和烧录

### 芯片1

在 `sanpo_board_config.h` 中设置：

```c
#define SANPO_BUILD_TARGET_MCU  1U
```

Clean、Build 后，将生成的 `.elf` 烧录到 STM32(1)。芯片1本地 CAN1/CAN2 映射到物理 CAN-1/CAN-2。

### 芯片2

将配置改为：

```c
#define SANPO_BUILD_TARGET_MCU  2U
```

重新 Clean、Build，再将新生成的 `.elf` 烧录到 STM32(2)。芯片2本地 CAN1/CAN2映射到物理 CAN-3/CAN-4。

两颗芯片不能直接共用同一次编译产物，修改目标芯片后必须重新编译。

## 6. 推荐实验流程

### 阶段一：无电机验证

1. 不接电机动力电源；
2. 分别烧录两颗芯片；
3. 插USB后确认两个COM口；
4. 使用 `BOARD_INFO` 确认 `board_id` 和CAN映射；
5. 使用PC SDK运行：

```powershell
python examples\board_test.py COM32
python examples\board_test.py COM33
```

没有电机时，`BOARD_INFO` 和 `HEARTBEAT` 应成功；`GET_STATE` 返回 `status=4` 属于预期。

### 阶段二：单电机CAN验证

1. 只连接一个电机；
2. 检查电机供电、CANH、CANL、GND和终端电阻；
3. 确认电机ID、CAN通道和CAN波特率；
4. 只修改对应关节配置；
5. 先运行 `GET_STATE`；
6. 确认 `online=1`、角度、速度和电流值合理；
7. 再运行 `CLEAR_FAULT` 和 `STOP_ALL`；
8. 脱离机械负载，以小于5°、低于1rpm测试运动。

### 阶段三：方向、零点和限位标定

1. 目标角度设置为小正角度；
2. 观察实际运动方向；
3. 方向相反则把 `direction` 改为 `-1`；
4. 回到机械基准点，记录并修改 `zero_deg`；
5. 逐步测试正负软限位；
6. 确认每个关节的最大电流和最大速度；
7. 最后才连接完整机械臂。

## 7. PC SDK 示例

```python
from sanpo_robot import SanpoBoard

board = SanpoBoard("COM32")
try:
    print(board.board_info())
    board.heartbeat()
    print(board.get_state(1))
    board.stop_all()
finally:
    board.close()
```

发送运动命令示例：

```python
board.move_joint(
    joint_id=1,
    angle_deg=5.0,
    speed_rpm=0.5,
)
```

首次运动时建议将角度设为 `1.0°`，速度设为 `0.2rpm`，并准备断电或急停。

## 8. 状态码与故障排查

| 状态码 | 名称 | 处理 |
|---:|---|---|
| `0` | OK | 命令成功 |
| `1` | BAD_FRAME | 检查帧长度、DLC和命令数据 |
| `2` | BAD_PARAM | 检查关节号、角度、速度或配置 |
| `3` | CAN_ERROR | 检查CAN初始化、总线和电机供电 |
| `4` | OFFLINE | 没有收到电机状态反馈 |

如果 `BOARD_INFO` 超时，优先检查USB固件、`SanpoApp_Process()` 是否运行、COM口是否正确；如果 `BOARD_INFO` 正常而 `GET_STATE` 为4，优先检查电机CAN链路和电机协议参数。

## 9. 当前实现边界

- 当前应用只解析标准CAN帧，不解析扩展CAN帧；
- 当前电机反馈按 `0xA4/0xAE` 格式解析；
- 当前控制帧按 `0xB2/0xB3/0xC2/0xC4/0xAF/0xCF` 实现；
- 这些命令和字节布局必须与实际电机型号协议一致；
- 电机协议不一致时，需要修改 `sanpo_motor_manager.c` 和状态解析函数；
- 最大电流、方向、零点、减速比和软限位目前均需要实机标定；
- 软件软限位不能替代硬件急停和机械限位；
- PC应串行发送应用命令，避免原厂ST协议没有序号字段造成响应匹配错误。
