# SANPO 五关节协同控制与完整调试说明

## 1. 交付内容与适用范围

本工程面向 STM32F407VET6 双 MCU 控制板。每颗 MCU 通过一个独立 USB CDC 串口与 PC 通信，并管理本地 CAN1、CAN2；物理接口上 MCU1 对应 CAN1/CAN2，MCU2 对应 CAN3/CAN4。

本版本保留原厂 ST/ET USB-CAN 通路，并增加：

- 五个关节目标角度暂存和一次性校验；
- 按各轴行程比例计算电机转速，使五轴尽量同时到达；
- 五轴统一启动、状态查询、故障掩码和超时急停；
- PC SDK 的 `move_group()` 接口和安全预览测试程序。

> `Release/original_factory_firmware_v4.bin` 是原工程附带的旧固件，不含本次功能。必须在 STM32CubeIDE 中重新 Build，使用新生成的 `.bin` 烧录。

## 2. 协同控制原理

PC 依次暂存 J1～J5 目标值，再发送统一执行命令。STM32 只有在五轴目标齐全、全部电机在线、无故障、角度不超软限位、计算速度不超上限时才开始运动。

各轴速度计算公式：

```text
motor_rpm = abs(target_deg - actual_deg) × gear_ratio × 60000
            / (360 × duration_ms)
```

行程较长的关节速度更高，行程较短的关节速度更低，理论到达时间一致。由于 CAN 命令逐帧发送，各轴实际启动存在很小的帧间延迟，并非硬件同步触发。

## 4. 上位机与 STM32 通信协议

### 4.1 ST 帧

| 偏移 | 长度 | 字段 | 说明 |
| ---: | ---: | --- | --- |
| 0 | 2 | Header | ASCII `ST`，即 `53 54` |
| 2 | 1 | Channel | 应用通道固定 `FE` |
| 3 | 2 | Reserved | 固定 `00 00` |
| 5 | 2 | CAN ID | 大端；请求 `07 F0`，响应 `07 F1` |
| 7 | 1 | DLC | 0～8 |
| 8 | DLC | Data | 应用命令和参数 |
| 8+DLC | 2 | Tail | `0D 0A` |

应用请求 ID 为 `0x7F0`，响应 ID 为 `0x7F1`。应用通道 `0xFE` 不发送到物理 CAN。其他普通 ST/ET 帧仍交给原厂静态库处理。

### 4.2 命令表

| 命令 | 请求 Data | 成功响应 Data | 功能 |
| --- | --- | --- | --- |
| `01 BOARD_INFO` | `01` | `81 00 + 6字节信息` | 板号、臂号、CAN 映射、轴数、版本 |
| `02 MOVE_JOINT` | `02 joint angle_i32 speed_u16` | `82 00 joint` | 单轴绝对角度运动 |
| `03 GET_STATE` | `03 joint` | `83 status joint angle_i16 speed_i16 fault` | 单轴状态 |
| `04 STOP_ALL` | `04` | `84 00` | 全部禁用/急停 |
| `05 HEARTBEAT` | `05` | `85 00` | 刷新 PC 看门狗 |
| `06 HOME` | `06 joint` | `86 00 joint` | 电机回零 |
| `07 CLEAR_FAULT` | `07 joint` | `87 00 joint` | 清故障 |
| `08 STAGE_GROUP` | `08 joint angle_i32` | `88 00 joint` | 暂存一轴协同目标 |
| `09 EXECUTE_GROUP` | `09 duration_u16` | `89 00` | 校验并启动五轴 |
| `0A GROUP_STATUS` | `0A` | `8A 00 + 6字节状态` | 查询协同状态 |

多字节应用参数均为小端。角度单位 `0.01°`，速度单位 `0.01 rpm`，协同时长单位 ms。

响应状态：

| 状态 | 含义 |
| ---: | --- |
| `00` | 成功 |
| `01` | 帧长度错误 |
| `02` | 参数错误、暂存不完整、超限或时长不合理 |
| `03` | CAN 发送失败 |
| `04` | 有电机离线或故障，禁止协同启动 |

J1 暂存 `10.00°`：

```text
53 54 FE 00 00 07 F0 06 08 01 E8 03 00 00 0D 0A
```

暂存完 J1～J5 后，以 5000 ms 执行：

```text
53 54 FE 00 00 07 F0 03 09 88 13 0D 0A
```

五个目标未全部暂存时，执行命令返回 `02`，不会启动任何轴。

### 4.3 GROUP_STATUS

| 字节 | 字段 | 说明 |
| ---: | --- | --- |
| 0 | staged_mask | 已暂存轴位图，bit0～bit4 对应 J1～J5 |
| 1 | active_mask | 仍在运动的轴位图 |
| 2 | done_mask | 已到位轴位图 |
| 3 | fault_mask | 故障或离线轴位图 |
| 4 | sequence | 每次成功执行后加 1 |
| 5 | active | `1` 表示协同动作进行中 |

例如 `fault_mask=0x04` 表示 J3 异常。

## 5. STM32 与电机 CAN 协议

当前使用标准 11 位 CAN ID，ID 取每轴 `motor_id`。

| 命令字 | 数据 | 当前用途 |
| ---: | --- | --- |
| `A4` | 单字节查询 | 周期读取综合状态 |
| `AF` | 单字节 | 清故障 |
| `B2 + i32` | 5 字节 | 速度上限，缩放 rpm×100 |
| `B3 + i32` | 5 字节 | 电流上限，缩放 A×1000 |
| `C2 + i32` | 5 字节 | 绝对位置，16384 count/圈 |
| `C4` | 单字节 | 回零 |
| `CF` | 单字节 | 禁用/全停 |

`A4` 响应当前解析布局：

```text
data[0] = A4
data[2..3] = current_i16，小端，0.001 A
data[4..5] = speed_i16，小端，0.01 rpm
data[6..7] = single_angle_u16，小端，16384 count/圈
```

若实际电机协议版本不同，修改 `sanpo_motor_manager.c` 的命令构造和 `SanpoMotor_OnCan()`，同时同步文档和 PC 端单位定义。

## 6. 机械臂参数适配

编辑 `Core/App/config/sanpo_joint_config.h`：

```c
{joint_id, motor_id, can_channel, direction, gear_ratio,
 zero_deg, min_deg, max_deg, max_rpm, max_current_a}
```

| 参数 | 校准方法 |
| --- | --- |
| `motor_id` | 单电机查询确认 ID，避免同 CAN 重复 |
| `can_channel` | 当前 MCU 本地只能写 `1` 或 `2` |
| `direction` | 发很小正角度；方向正确填 `1`，相反填 `-1` |
| `gear_ratio` | 电机转数/关节输出转数，例如 3:1 填 `3.0f` |
| `zero_deg` | 机械零位时希望上位机显示的角度 |
| `min_deg/max_deg` | 初期比机械安全范围各缩小 10°～20° |
| `max_rpm` | 电机轴最大允许转速 |
| `max_current_a` | 从低值开始，确认负载后逐步提高 |

换算公式：

```text
motor_deg = (joint_deg - zero_deg) × direction × gear_ratio
joint_deg = motor_count × 360 / 16384 / gear_ratio × direction + zero_deg
```

推荐顺序：卸载并准备急停 → 单电机确认 ID/CAN → 低电流低速 → `+2°` 校准方向 → 外部量角校准减速比 → 确定零点 → 设置保守软限位 → 五轴分别通过后再协同。

## 7. MCU1、MCU2 编译和烧录

`sanpo_board_config.h`：

```c
#define SANPO_BUILD_TARGET_MCU 1U
```

- MCU1：保持 `1U`，构建后命名 `SANPO_MCU1_five_joint.bin`。
- MCU2：改为 `2U`，Clean 后重建，命名 `SANPO_MCU2_five_joint.bin`。

该宏改变板号、臂号和物理 CAN 编号说明；每颗 MCU 内部句柄仍是 CAN1/CAN2。若左右臂参数不同，应建立两套关节参数表。

构建步骤：

1. CubeIDE：`File -> Import -> Existing Projects into Workspace`。
2. 选择工程根目录。
3. 修改 MCU 身份和关节参数。
4. `Project -> Clean`，再 `Build Project`。
5. `.cproject` 已启用 Binary Output Converter；在构建目录获取 `.bin`。
6. ST-LINK 连接对应 STM32F407VET6，Flash 地址 `0x08000000`。
7. 烧录、断电重启，确认 Windows 出现 USB CDC COM 口。

若没有 BIN：

```text
Project Properties -> C/C++ Build -> Settings
-> MCU Post build outputs -> Convert to binary file
```

不要添加引用错误 ELF 文件名的手写 post-build 命令。

## 8. PC SDK

安装：

```powershell
cd pc_sdk
python -m pip install -r requirements.txt
python -m pip install -e .
python examples\board_test.py COM33
```

先安全预览：

```powershell
python examples\five_joint_coordinated_test.py COM33 `
  --angles 0 0 0 0 0 --duration 5000
```

确认后执行：

```powershell
python examples\five_joint_coordinated_test.py COM33 `
  --angles 5 -5 5 0 0 --duration 5000 --execute
```

API：

```python
from sanpo_robot import SanpoBoard

board = SanpoBoard("COM33")
try:
    result = board.move_group(
        angles_deg=[5.0, -5.0, 5.0, 0.0, 0.0],
        duration_ms=5000,
        wait=True,
    )
    print(result)
finally:
    board.close()
```

`wait=True` 持续查询状态，也会刷新 PC 看门狗。`wait=False` 时必须至少每 2 秒调用一次 `heartbeat()` 或 `group_status()`，否则固件执行 `STOP_ALL`。

## 9. 分阶段调试

### A. USB（电机断电）

运行 `board_test.py`。`BOARD_INFO` 必须返回；电机离线正常。COM 不出现时，先刷原厂固件确认硬件，再检查 `StartDefaultTask()` 是否仍调用 `MX_USB_DEVICE_Init()`。

### B. CAN（只接 J1）

总线两端各 120 Ω，断电测 CANH-CANL 约 60 Ω。检查波特率、ID、通道、电源和共地。收到 A4 后 J1 才在线。若超时，检查过滤器、CAN2 RX0 NVIC 和 FIFO 回调。

### C. 单轴小角度

```powershell
python examples\small_angle_test.py COM33 `
  --joint 1 --angle 2 --speed 0.5
```

确认预览后加 `--execute`。逐轴验证方向、角度、速度和限位。

### D. 五轴协同

先使用接近当前位置的目标，首次时长 5000～10000 ms；再测试每轴 2°～5°。观察 `active_mask`、`done_mask`、`fault_mask`。任何方向、零点或比例错误立即停止并重新标定。

## 10. 现有功能

- 原厂 ST/ET USB-CAN 透传；
- MCU 身份和 CAN 映射查询；
- 五轴周期 A4 状态轮询；
- 单轴角度、速度、电流限制、状态、回零、清故障；
- 全轴禁用急停、软限位、PC 失联保护；
- 五轴暂存、统一校验、协同执行、完成/故障位图；
- CAN 中断只入缓冲，解析和 USB 回复在任务上下文执行；
- 不新增 FreeRTOS 任务，继续使用原 `defaultTask`。

## 11. 常见故障

| 现象 | 优先检查 |
| --- | --- |
| Python 提示缺少 `port` | 命令加入 `COM33` 等实际端口 |
| `BOARD_INFO timeout` | 是否烧录新固件、COM 是否正确、通道/ID 是否 FE/7F0 |
| 状态 `04` | 至少一轴未收到 A4，或已有故障 |
| 执行返回 `02` | 暂存不全、角度超限、时长超范围、所需 rpm 超限 |
| 约 2 秒后停止 | 使用 `wait=True`，或持续发心跳 |
| 回零角度反增 | `direction`、`zero_deg` 或回零方向错误 |
| 角度比例不对 | `gear_ratio` 或 16384 count/圈假设错误 |
| 烧录后 USB 消失 | 不要在 CDC 回调里等待 CAN 或直接回复 |
| CAN1 正常、CAN2 无数据 | CAN2 RX0 NVIC、过滤器 Bank、FIFO0 回调 |

## 12. 安全限制

本工程完成代码级检查和无硬件协同仿真，但机械参数仍是参考值，不能替代实机标定。首次烧录不得直接运行大角度动作；必须配备机械急停，采用低电流、低速度、空载/卸载条件逐轴确认。
